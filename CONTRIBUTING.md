# Contributing

Start with the README setup, then run `npm run check`, `npm run build`, and `npm run test:e2e`.

Keep changes focused on the pitch-practice experience. Include a reproduction for bugs and a short demonstration for interface changes. Update the README when setup or user-visible behavior changes.

Conversation changes should include tests for cancellation, pressure rules, and stale responses. Model changes should include examples from the labeled evaluation set. Use synthetic pitch data in fixtures and screenshots; never include private decks, transcripts, recordings, or credentials.

The sample is deliberately scripted. Keep sample results clearly labeled and never present them as live model output.
